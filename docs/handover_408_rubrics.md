## 三、这次查证出来的关键事实（比上一轮更准）

### 3.1 找到目录接口，不用再猜 URL

上一轮是"看到一个 2025 的 PDF 链接"，以为要逐年搜。实际上考研网有公开接口：

```
https://api.kaoyan.cn/pc/question/questionList?page=1&pageSize=10&first_type=4
https://static.kaoyan.cn/json/question/<question_id>.json    → data.file_url
```

`first_type=4` 是「统考类综合」，2011–2026 每年一份，**2009/2010 也在**（在后面几页）。
`json/question/<id>.json` 返回文档元数据（`file_url` / `doc_size` / 上传者）。

### 3.2 **18 年里只有 2025 一份能解析出评分标准**

逐份实测（详见 `data/408/rubrics/_coverage.md`）：

| 年份 | 文档状态 | 能不能出 rubric |
|---|---|---|
| 2009–2014 | 纯扫描件（0 行文字层） | ✗ |
| 2015–2018 | 答案册文字层，有「解答」，2015–2017 还带【评分说明】 | ✗（评分说明是零散加分规则，凑不出步骤分值） |
| 2019–2026 | 多数只有题目（2023/2024 是回忆版），或只有解析 | ✗（2025 除外） |
| **2025** | 含【评分标准】原文，41 题分档完整 | **✓** |

也就是说：**"权威源存在且可机读"这条上一轮的结论只对 2025 年成立**。
公开资料里 408 综合题的分档细则本身就很少见（和主观题阅卷细则不公开同一个原因）。

### 3.3 搜索接口不能用（踩过）

`keyword=408` 会把 2024/2023 各 170+ 条「自命题」重复项翻出来（全部指向同一份试卷），
翻到第 30 页都到不了 2015 年。**必须用 `first_type=4` 分页浏览**。

### 3.4 顺便发现的两个数据问题

- `data/408/question_tags.json` 里 2018 年第 42 题题干写「（12 分）」，但分值字段是 10；
  2021 年第 44 题题干写「（8 分）」，分值字段是 10。**题干分值不可全信**，
  rubric 校验一律以题库 `分值` 为第二依据（脚本里已双向比对）。
- `score_generic()` 的"分点"识别**不认全角（1）（2）** —— 而 408 综合题的标准写法
  恰恰是「（1）…（2）…」，于是分点项永远判 0。已修（见 `yj/rubric_checker.py`）。

## 四、判分是怎么做的（改之前先看）

`score_by_rubric(answer, rubric, full, reference, terms)`：

1. 按学生写的「（1）（2）（3）」把作答切段，每段对应 rubric 的一个步骤；
   没分步就整段判（会略低估）。
2. 每个步骤按**评分标准措辞**决定看什么证据：
   - 名字里有「思想/设计」→ 看思路描述的长度；
   - 有「实现/代码」→ 看有没有代码特征（关键字+花括号/分号）；
   - 有「注释」→ 看有没有 `//` 或「注释」；
   - 有条件里出现 `O(n)` → 看学生写的复杂度和题目要求是否一致。
3. 证据合成 0–1 的质量分，再按档次的阈值选档，**分数落在该档区间内**
   （`2-3 分`就取 2~3，`最高 5 分`就取 ≤5）。
4. 有参考答案时，用中文 2-gram 重合度校正"是不是答到点子上"；
   几乎不沾边且篇幅很短 → 压到 0。
5. 输出每步的档、得分、没做到的点（"漏了空间复杂度 —— 这一步 2 分"）。

**必须承认的边界**：机器读不懂代码，也判断不了算法思想对不对。
所以界面标题写「官方评分标准」（指依据是原文），副标题仍保留
"机器按证据估算"，不能让它看起来像阅卷分数。

## 五、下一轮可做的（按性价比排序）

1. **补 rubric 数据（价值最高）**
   - 2025 的【评分标准】来自某机构的解析册；同系列解析册若能在公开渠道拿到
     其它年份的 41 题分档，直接丢进 `.cache/408_ky/<年>.pdf` 再跑脚本即可。
   - 备选：CSDN 那个「408 真题详解」系列（`chenby186119`）有【评分要点】，
     但**一年一篇、格式各异、且是 AI 风格改写**，要单独写解析器；
     上一轮已经因为同样的原因放弃了它，这次仍然没走这条路。
2. **41 题模板化**：408 第 41 题（算法设计）的官方给分结构多年稳定
   （思想 4 分 / 代码 7 分 / 复杂度 2 分，2025 原文就是这三步）。
   若要覆盖其余年份，可以"套用 41 题模板 + 用题干括号里的分值"，
   但**必须在界面上标成"模板套用"，不能冒充官方标准** —— 这条路我没做，
   因为会稀释"官方"两个字的分量，需要产品上点头。
3. **政治**：仍是结构体检。`《考试分析》` 只有纸质/付费电子版，
   且用户明确要求"这条限制不要写进界面"，所以没动。
4. 若以后 rubric 变多：`rubric_for()` 是按 `<年>.json` + 题号查的，
   加文件即可，不用改代码；`tests/test_rubric.py` 记得补对应年份的样本。

## 六、坑（更新）

1. `web_fetch` 不支持 PDF → `curl` 下载到本地再 `norm_lines()`。
2. 知乎 403（要登录），别指望。
3. **考研网不要用 keyword 搜索**，用 `first_type=4` 分页（见 3.3）。
4. 政治分析题在 `data/zhengzhi/` 里没有任何参考答案（85 道，解析全空）。
5. 本地 `.cache/408/*-answer.pdf` 是扫描版；`data/solutions/*.json` 是带水印的 OCR
   （"公众号：计算机考研数据"），**不能做相似度比对**，只能做关键词校正
   （`score_by_rubric` 里已做去水印）。
6. 2025 的 PDF 里 `O(n²)` 的上标会丢，被抽成 `O(n)` —— 解析 rubric 时不要把
   括号里的复杂度当成唯一判据（现在只用它做"是否达标"的软证据）。
