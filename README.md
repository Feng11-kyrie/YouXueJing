# 优学鲸 · 408 考研知识图谱

面向 408 考研（计算机学科专业基础综合）的**知识点图谱与真题标注数据集**。

本仓库是整个「优学鲸」项目的**数据层**：把官方考试大纲结构化成知识点图谱，
再用 18 年（2009–2026）共 846 道真题完成考点标注，并构建知识点前置依赖图。

> ⚠️ **本仓库不包含试题原文。** 详见下方[版权与数据边界](#版权与数据边界)。

---

## 这份数据集有什么

| 资产 | 规模 | 说明 |
|---|---|---|
| **考纲知识点树** | 4 学科 / 24 章 / 116 节 / 214 考点 | 依据官方考试大纲逐条结构化 |
| **叶子候选集** | 266 个 | 打标用的最小粒度单元（树深度变长，故按叶子而非固定层） |
| **真题考点标注** | **846 题**（720 单选 + 126 综合） | 每题 1 个主考点 + 0–2 个次考点 + 难度 + 置信度 |
| **考点频次统计** | 266 个考点 × 18 年 | 234 个考点被考到（88%），32 个从未考过 |
| **知识点依赖图** | **339 条前置边**（无环 DAG） | 支撑「薄弱点 → 追溯根因 → 补前置」 |
| **诊断题库** | **32 题 / 覆盖 24 章** | 新用户冷启动：做题即得章节级掌握度 |

## 为什么做这个

个性化学习推荐的关键不是「给你一堆题」，而是**找到知识断点**。

举例：用户画像显示「红黑树」掌握度 35%。没有依赖图时系统只能推红黑树的题——用户依然做不出。
有了依赖图，系统会向上追溯前置链：

```
红黑树              35%
  ↑ 前置
平衡二叉树           42%   ★ 断裂点
  ↑ 前置
二叉搜索树           38%   ★ 断裂点
  ↑ 前置
二叉树的定义及主要特性  88%   ✓ 已掌握
```

→ 正确动作是**先补「二叉搜索树」**，而不是练红黑树。

这就是本仓库「依赖图」存在的原因。

## 方法论

### 1. 打标粒度：叶子级

树的**深度是变长的**——大纲对四门课的细化程度不同：

| 学科 | 叶子所在层级 | 叶子数 |
|---|---|---|
| 数据结构 | 多在 L3（节） | 56 |
| 计算机组成原理 | 多在 L4（考点） | 64 |
| 操作系统 | 多在 L4（考点） | 61 |
| 计算机网络 | 多在 L4（考点） | 80 |

因此统一标到**叶子节点**（不管它在第几层），展示时再向上聚合到章/节。

### 2. 打标用封闭候选集

先由题号区间确定学科，再在**该学科的 56–80 个叶子**中选择（而非全量 266 选 1）。
候选集封闭意味着模型不会发明大纲外的知识点——**846 条标注中自造 id 数为 0**。

### 3. 双重校验修正学科归属

最初假设「学科由题号区间唯一确定」，但**该假设对 4 个年份不成立**。用两道独立证据裁决：

- **官方分值硬约束**：单选固定 80 分 → 综合题必为 数据结构 2题23分 / 组成原理 2题23分 / 操作系统 2题15分 / 计算机网络 1题9分（纯算术，可穷举验证）
- **题干内容判定**：逐题读题干判断学科

两者结论完全一致，共修正 10 道题（2009 / 2014 / 2016 / 2019）。

### 4. 依赖边两个来源

| 来源 | 边数 | 依据 |
|---|---|---|
| 同节链式 | 150 | 大纲在同一节内按学习顺序列出子考点，相邻两者构成前置链 |
| 跨节共现 | 234 | 从 846 题「主考点+次考点」共现挖掘，且前置在考纲顺序上更早 |

方向以**考纲全序**为先验（前置必然更早），因此在数学上不会成环。

## 诊断题库（冷启动）

个性化推荐的前提是知道用户弱在哪，但新用户没有任何作答记录。靠聊天问「你哪科弱」
主观且失真，靠做题测出来才客观 —— 这就是诊断题库的作用。

**设计**：每科 8 题共 **32 题**（约 20-25 分钟），两轮选章：

- 第一轮 **每章 1 题** → 覆盖全部 **24 章**
- 第二轮按 **18 年考频** 补足到每科 8 题 → 高频章节加密

三条选题约束：

| 约束 | 原因 |
|---|---|
| **只用纯文字单选** | 排除需插图题，避免用户看不到图而误答（与能力无关） |
| **难度优先 2-3** | 诊断不是选拔，避免一上来就打击 |
| **年份分散**（实际跨 8 个年份） | 最新两年的真题是学生最可能已刷过的，集中使用会虚高掌握度 |

**评分**：章节掌握度 = (答对+1)/(题数+2)（Laplace 平滑，避免 0% 与 100% 极端）→ 作为画像初始值。

> 只做**章节级粗粒度聚合**，不做知识追踪模型 —— 申报表明确「不做精细化学情诊断」。

### 为什么首屏不是诊断

最初的设计是"进来先做 32 题诊断"。**这是错的**：32 题要 20-25 分钟，
大部分人在看到任何价值之前就走了 —— 激活率杀手。

改为**用户自己挑**：进来几次点击就能练上题，摩擦最小、掌控感最强。
**他的勾选直接进入画像**，与做题数据同等对待（`yj/store.py::set_marks`）。

诊断从门槛降级为可选项：想更准的人可以去做，不想做的人照样能用。

> 两条数据来源任一存在，整条链路就能跑：作答记录 或 自报标记。
> 这一点写在图的条件边上（`yj/graph.py::route_after_load`）——
> 早期只看作答记录，导致"只勾选不作答"的用户被挡在链路外。

### 三个关键设计

**1. 不做注册登录。** 用户身份是浏览器 localStorage 里的 uuid，零门槛。
账号体系是单人项目崩溃与拖延的第一来源，且对路演零加分。

**2. Laplace 平滑掌握度。** 掌握度 =（答对+1）/（题数+2）。
不平滑的话只答 1 题答对就是 100%、答错就是 0%，会给出极端且不稳的推荐。

**3. 路径推荐有三条，而非一条。** 因为"该怎么学"取决于用户的时间和基础：

| 路径 | 机制 | 适合 |
|---|---|---|
| 补根因 | 沿依赖图向上追溯**断裂点**，从最靠前的前置开始补 | 基础不牢 |
| 冲高频 | 只挑 18 年考频最高且未掌握的考点 | 时间紧 |
| 错题驱动 | 从做错的题反推考点，错得多的先补 | 已练过题 |

**「补根因」是差异化的核心**：用户说"红黑树弱"，根因可能是"二叉搜索树"。
所以不能直接推薄弱点，要沿依赖边向上走，直到找到一个已经掌握的节点 —— 那才是该开始补的地方。

依赖边的章级聚合说明见 `yj/data.py::chapter_prereqs()`：叶子级依赖有 339 条，
但诊断只有 32 题、每章 1-2 题，叶子级掌握度太稀疏，因此聚合成 24 个章级依赖用于冷启动。

## 多智能体编排（LangGraph StateGraph）

```
准备 Agent → 诊断 Agent → 画像 Agent → 路径 Agent → 生成 Agent → 复核 Agent
     │
     └─(条件边) 没有作答记录 → 直接要求先诊断，不进后续节点
```

六个节点各司其职，状态在节点间显式传递，因此每一步的输入输出都可检查。
条件边让"数据不足就走另一条路"成为图的一部分，而不是散落在代码里的 if。
实际编译出的图可在界面「⑤ 资源生成」里看到（含条件边）。

**为什么「复核 Agent」不用 LLM**：它做的是**程序化校验** —— 检查生成文本里的
小标题/加粗词是否都能在考纲 266 个叶子考点中找到。这是可重复、可验证的防幻觉措施，
比"再让一个 LLM 审一遍"可靠得多。

### LLM 可配置，且无 key 时不假装

| 情形 | 行为 | 界面标注 |
|---|---|---|
| 配了 API key | 调 LLM 生成讲解正文 | "LLM 生成" |
| 命中预跑缓存 | 直接读缓存 | "LLM 生成（预跑缓存）" |
| 未配 key | **用真实数据填模板** | "模板模式（真实数据）" |
| 调用失败 | 降级为模板 | "LLM 失败，已降级为模板" |

**模板模式不是"假 AI 输出"**：它给的都是真数据（考频、真题清单、前置掌握度），
只是没有 LLM 写的讲解文字。界面上必须标清 —— 对外表述要真实。

配置方式（任选其一）：

```bash
export LLM_API_KEY=sk-xxx
export LLM_BASE_URL=https://api.deepseek.com/v1
export LLM_MODEL=deepseek-chat
```

或写进 `.streamlit/secrets.toml`：

```toml
[llm]
api_key = "sk-xxx"
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"
```

### 缓存键必须带模型

缓存键 = 任务 + 输入 + **模型/服务地址** + 提示词版本。带上模型是必须的：
否则从 `deepseek-chat` 换到别的模型时会命中上一个模型的输出，
表现为"换了模型但结果没变"，极难排查。

### 测试

```bash
.venv/bin/python tests/test_llm_stub.py
```

用桩替换 `openai` 客户端，**在没有 API key 的前提下**验证 LLM 通路：
配置读取、成功调用、**缓存命中后不再调 API**、重试与降级、来源标注，
以及复核 Agent 对 LLM 文本的考纲校验（能识别"量子计算加速"这类越纲内容，
且不误报"平衡二叉树"）。

唯一未被覆盖的是**真实网络调用本身**（鉴权/额度/模型名/响应格式）—— 那需要真 key。

> 该测试使用独立的临时数据库。曾经它共用生产缓存，把桩内容写进了缓存，
> 真实预跑命中后导致路演快照里混入假内容 —— 这类污染排查起来很费劲，
> 所以测试隔离是硬要求。

## 数据质量清洗

PDF 的文字层会带进大量版式噪声。清洗前实测 **213/846 题（25.2%）被污染**，共修复 **313 处**：

| 问题 | 处数 | 示例 | 处理 |
|---|---|---|---|
| **页眉页脚混入**（最严重） | 183 | 选项末尾被塞进「2009 年全国硕士研究生入学统一考试…第2页，共10页」 | 按模式删除整行 |
| **上标被拆成独立行** | 78 | `2⏎7⏎×⏎29/32` 实为 `2^7 × 29/32` | 还原为 `^` 记法 |
| 运算符独占一行 | 33 | `2⏎32⏎ – 2⏎15⏎ + 1` | 换行化为空格 |
| 章节标题混入 | 18 | 「二、综合应用题（第41～47 题，共70 分）」 | 按模式删除 |

**其中页眉页脚污染最值得注意**：它会出现在**选项文本里**，用户会直接看到一整行试卷页眉。

上标统一写成 ASCII 的 `^` 记法（如 `2^7`）而非 Unicode 上标（`2⁷`）——后者会破坏下游检索与匹配，渲染成真正的上标是前端的职责。

清洗后复查：5 类污染**残留均为 0**，846 题结构与 720 个答案完好无损。

## 插图抽取

118 道题的题干里有「如图」「如题 7 图所示」这类引用，但图是 PDF 里的位图，不在文字层里。
`extract_figures.py` 把插图抽出来并映射回题目，成功 **102 题**。

映射依据分四级（`_图片依据` 字段可审计）：

| 依据 | 题数 | 含义 |
|---|---|---|
| 题注 | 30 | 图下方/上方有「题 N 图」字样，直接给出题号 |
| 题干引用 | 57 | 该题题干含插图引用（`FIG_RE`），取图片上方最近的一道 |
| 需插图标记 | 4 | 由上述规则间接定位 |
| 就近回落 | 11 | 无题注也无引用，按版面就近归属（置信最低） |

抽取过程中处理了四个坑：

1. **页面级变换** —— 内容流开头的 `0.75 0 0 -0.75 0 841.92 cm` 必须先套用，
   否则所有坐标都是错的。但部分年份（如 2024）**没有**这个变换，其内容流的
   第一个 `cm` 其实是某张图的放置矩阵，误当成页面变换会让坐标全部跑飞。
2. **`page.images` 的顺序不是视觉顺序** —— 必须从内容流解析 `cm` + `Do` 拿真实坐标，
   再配合题注位置配对。
3. **图可能包在 Form XObject 里** —— 2024 年的插图是 `/Meta38 -> /Image39` 这样的嵌套结构，
   需要递归进 Form 并复合其 `/Matrix` 与 `/Resources`；同时不能把所有 `/Name Do`
   都当图片（Form 也可能是矢量绘制）。
4. **一条图被切成多张横条** —— 2018 年第 44 题的图被切成 11 条，需按坐标识别相邻块并纵向拼接。

另外还需处理两类编码：JPEG 交给 PIL 直接读；**`/FlateDecode` 原始像素**（2023/2024 部分插图）
PIL 认不出，要按 `/ColorSpace` 与 `/Width /Height /BitsPerComponent` 自行重建。

## 已知局限

- **27 道题正文引用了插图但没有抽到图**（`_缺图: true`）。其中大多数是「如下所示」实为
  **内联表格或代码**（伪代码、段表、指令格式），本就不需要位图；少数是真实缺口，需人工补。
- **11 道题按版面就近归属插图**（`_图片依据: 就近回落`），置信最低，建议人工复核。
- **依赖边中 127 条仅单次共现**（置信度 0.5），证据较弱，需人工复核。每条边的「依据」字段可直接判断是否成立。
- **跨学科依赖尚未构建**（如组成原理的「存储层次」↔ 操作系统的「内存管理」）。
- **综合应用题无客观答案**（主观题），自动判分只覆盖 720 道单选；综合题另提供
  「免费反馈」（有官方评分标准时按分档给分，否则只做结构体检），**不是阅卷分数**
  （覆盖率与数据来源见 `docs/handover_408_rubrics.md`）。
- **408 客观题答案**：与 `data/408/answers_verified.json` 校订库逐题一致（720/720），
  出处按年在案（11 年读图录入、7 年自动提取并与解析交叉校验）。
  单选题解析为 AI 生成，2026-10 复核时发现 2 条解析与答案矛盾（2020 第 14 题、
  2022 第 15 题），已改写；界面不再标注"未经官方核验"。
- **政治客观题答案**：2026-10 已逐年核对 2010–2026（多份公开答案表交叉 + 题源解析）：
  - **2017 年卷已补**：原来的 `2017.json` 其实是 2018 年卷（题干相似度 0.94）。
    已换成考研网（kaoyan.cn）的 2017 真题文档：真实 38 题 + 33 个答案 + 逐题解析。
  - **2015 年解析器 bug 已修**：`parse_zhengzhi.py` 会把「（答案：ABC）」里的 A 当成选项标记，
    导致 12 道题的选项 A 变成「BC）A．…」。修了选项切分正则，人工裁定 3 题
    （17→ABD、28→AB、32→ABD）。
  - **共修正 20 个答案**（2010×2、2013×2、2015×3、2016×6、2018×2、2023×3、2024×2），
    全部记录在 `scripts/zz_manual_answers.py`（含判定依据，可重复应用）。
  - 2011/2012/2014/2019/2020/2021/2022/2025/2026 核对一致；个别字母冲突经**选项文字**
    比对确认是「一题多卷」的选项顺序差异，未改。
  - 公开资料本身仍有 1–2 处分歧（如 2021 第 24 题 ABCD/BCD/ABD 三派并存），已在
    `scripts/zz_manual_answers.py` 注释里记录。
  - 因此政治解析不再标注「AI 生成（未经官方核验）」；题源抽取的解析仍标「题源」。
  - **分析题（34–38）参考要点**：2026-10 起由服务端 LLM 补写
    （`scripts/gen_zz_analysis_refs.py`），界面标注「AI 参考要点（非官方）」；
    免费评分因此从纯结构体检升级为「结构体检 + 参考要点覆盖」，仍**不是阅卷分数**。
  - **四科内容体检**：`scripts/audit_subjects.py` 统计题数/客观答案/解析/主观参考，
    输出 `docs/audit_content.md`；`tests/test_free_score.py` 保证四科免费评分都能给出分数。
- **考点掌握度数据不在此仓库**（属于运行时用户数据）。
- 大纲各考点的「掌握 / 理解 / 了解」要求等级未包含——公开转载版大纲不含该信息。

## 数学真题（2026-10 新增）

- **覆盖**：数学一 / 数学二 / 数学三，2010–2025 共 48 套卷、1112 题。
  2010–2020 每卷 8 选择 + 6 填空 + 9 解答；2021 起 10 + 6 + 6，满分 150。
- **来源**：
  - 数一 2010–2020：TsekaLuk/Kaoyan-Math1-Papers（Markdown/LaTeX 题库 + 详细解析）；
  - 数一其余年份与数二/数三：lx-ruc/kaoyanshuxue 的飞书文档导出（真题墙，含答案与解析）。
    数三另按题目图片逐题转录/校对，处理记录写进每题 `备注`。
- **答案校验**：422 道选择题与同仓库 `answers.json`（真题墙）逐题比对，**0 处不一致**；
  数一 2010–2020 另与 TsekaLuk 解析交叉校验，选择题答案同样全一致。
- **公式渲染**：本地 **KaTeX**（`static/katex/`，前端渲染，离线可用）；
  服务端只做坏 LaTeX 修补与 HTML 转义（见 `yj/mathrender.py`）。
- **判分**：
  - 选择题：点选项即判对错（答案来自题库）。
  - 填空题：先把 `\frac{1}{2}`、`\sqrt{2}`、`\pi` 等压成可比的写法再比；对不上时给出
    参考答案，并保留「我写对了 / 写错了」手工判定（公式写法不同不可能 100% 自动比对）。
  - 解答题：手写题，看解析自评；另有**免费评分**（`yj/math_checker.py`，按参考答案的
    关键步骤覆盖率 + 分步结构 + 篇幅做「结构体检」）与 **BYOK 的 AI 精评**。
    两者都**不是阅卷分数**。
- **诊断闭环（2026-10 新增）**：`/diagnose?exam=MATH&tier=一` 按考点抽 **12 道选择题**，
  交卷后给考点掌握度与薄弱 Top 5；真题页支持**按考点筛题**（`&point=…`）与**只错题重练**；
  首页「今天建议先补」按科目各给一张卡（408 / 数学）；「我的画像」「我的薄弱点」都有数学段，
  弱考点可按该考点真题生成**速记**（AI，缓存到本地）。数一/二/三 各自独立（考点 68 / 45 / 57）。
- **配图**：12 道题保留**题图**——11 道是题干本身引用函数图像/曲线图（「如图所示」），
  文字无法替代；1 道是 2009 数三题干在文字源里缺失（2010–2025 范围内没有纯图片题）。
  其余原本靠图片的题已逐题文本化，不再展示原图，也没有「查看原图」入口。
  （图在本地 `data/math/figures/`，不进版本控制。）
- **已知局限**：
  - 少数解析的分段函数/多行公式被文档导出时打乱顺序，文字是原文但渲染可能错位；
  - 数三有 17 道题按图片转录/校对，可能有转写误差（每题 `备注` 已标）；
  - 免费评分只看「答到哪些关键步骤」，判断不了推导是否真的正确。

## 四科诊断与建议（2026-10）

- **408**：32 题章节诊断（既有）；**数学**：每考点抽 1 道选择题，12 题覆盖 12 个考点；
  **英语**：完形 20 + 阅读 5 + 新题型 5，共 30 题（翻译/写作不自动诊断）；
